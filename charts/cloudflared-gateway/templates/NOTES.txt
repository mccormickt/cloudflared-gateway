{{ .Chart.Name }} {{ .Chart.AppVersion }} has been installed into namespace "{{ .Release.Namespace }}".

1. Verify the controller pod is running:

    kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}
    kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/instance={{ .Release.Name }} -f

2. Create a GatewayClass that claims this controller:

    apiVersion: gateway.networking.k8s.io/v1
    kind: GatewayClass
    metadata:
      name: cloudflared
    spec:
      controllerName: {{ .Values.controllerName }}

3. Create a Gateway and routes attached to it. Once reconciled, the controller
   provisions a Cloudflare Tunnel and deploys `cloudflared` pods in the Gateway's
   namespace. Example Gateway + HTTPRoute manifests live in the repo under
   `examples/`.

4. Find the provisioned tunnel in the Cloudflare dashboard:

    https://one.dash.cloudflare.com/ -> Networks -> Tunnels
{{- if .Values.dns.enabled }}

5. DNS management is ENABLED: the controller creates a proxied CNAME
   (hostname -> <tunnelID>.cfargotunnel.com) for each route hostname. Ensure the
   API token also carries Zone:Read + Zone:DNS:Edit. Annotate a Gateway with
   cloudflared-gateway.jan0ski.net/dns-managed: "false" to opt it out.
{{- else }}

5. DNS is NOT managed by the controller. For each route hostname, create a
   PROXIED CNAME to <tunnelID>.cfargotunnel.com (shown in the Gateway's
   status.addresses), or set dns.enabled=true to have the controller manage it
   (the API token then also needs Zone:Read + Zone:DNS:Edit).
{{- end }}

WARNING: No Cloudflare credentials were configured. The controller will fail
to start until a Secret named "{{ include "cloudflared-gateway.secretName" . }}"
exists in namespace "{{ .Release.Namespace }}" with keys `account-id` and
`api-token`, or until you re-run helm with `--set cloudflare.accountId=...`
`--set cloudflare.apiToken=...` or `--set cloudflare.existingSecret=...`.
{{- end }}
